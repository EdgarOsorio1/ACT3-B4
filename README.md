# ACT3-B4-Edgar-Osorio

Para esta actividad se creó un carrito de ventas en Angular donde varios componentes comparten el mismo estado a través de un servicio con Observables, y los subtotales y el total se calculan con pipes personalizados. La aplicación muestra una lista de productos a la izquierda y el carrito a la derecha, y cualquier cambio que se haga en uno se refleja de inmediato en el otro sin recargar la página.

El código se organizó en cinco carpetas dentro de src/app. En models está productoModel.ts, que define las interfaces Producto (id, nombre y precio) e ItemCarrito (el producto y la cantidad que se lleva). En services está carritoService.ts, que guarda y administra el estado del carrito. En pipes está calculosPipe.ts, con los dos pipes personalizados. En listaProductos está el componente que muestra los productos disponibles y permite agregarlos, y en resumenCarrito está el componente que muestra el contenido del carrito, los subtotales y el total. El componente principal, app.ts, solo junta a estos dos.

El corazón del flujo es CarritoService. Este servicio usa un BehaviorSubject como fuente de verdad del carrito: guarda la lista actual de productos y la emite a todos los que estén suscritos. Los componentes no pueden modificar esa lista directamente, porque el servicio solo expone un Observable de lectura llamado items$ y un conjunto de métodos para cambiar el estado. Los métodos son agregar, cambiarCantidad, eliminar y vaciar. Cada uno crea una lista nueva en lugar de modificar la anterior y la emite con next(), de esta forma todos los componentes suscritos reciben el cambio automáticamente. Si un producto ya está en el carrito, agregar solo le suma una unidad, y si la cantidad baja de 1, el producto se elimina.

La comunicación entre componentes se hace únicamente a través del servicio. El componente listaProductos no conoce al carrito: cuando se presiona "Agregar" solo le dice al servicio que agregue ese producto. El componente resumenCarrito tampoco conoce a la lista de productos: se suscribe al Observable items$ y muestra lo que el servicio le entrega. Esa suscripción se hace en el HTML con el pipe async, que se suscribe al abrir el componente y se desuscribe solo al destruirlo, por lo que no hay que manejar el unsubscribe a mano ni se generan fugas de memoria.

Se implementaron dos pipes personalizados. El pipe subtotal recibe el precio de un producto y su cantidad y devuelve el precio multiplicado por la cantidad; se usa en cada fila del carrito. El pipe totalCarrito recibe la lista completa de productos del carrito y devuelve la suma de todos los subtotales; se usa para mostrar el total general. Gracias a los pipes, los cálculos no están mezclados en el código de los componentes y la plantilla queda clara, porque basta leer la expresión para saber qué se calcula. Además se usó el pipe currency de Angular para mostrar los montos en quetzales, por ejemplo Q5,500.00.

En las plantillas se usaron las directivas *ngFor para recorrer la lista de productos y las filas del carrito, y *ngIf para mostrar el mensaje "El carrito está vacío" cuando no hay productos y para mostrar la tabla, el total y el botón de vaciar solo cuando sí los hay. El data binding con llaves dobles muestra los nombres, precios y cantidades, y los eventos (click) conectan los botones con los métodos de cada componente.

Se probó el funcionamiento completo del carrito. Al agregar un producto aparece en el carrito con cantidad 1 y su subtotal. Al agregar el mismo producto otra vez no se duplica la fila, solo sube la cantidad y se recalcula el subtotal. Los botones + y - cambian la cantidad y actualizan el subtotal y el total al instante. Si se baja la cantidad de 1 a 0, el producto se elimina del carrito. El botón "Quitar" elimina un producto sin importar su cantidad, y "Vaciar carrito" deja el carrito en cero y vuelve a mostrar el mensaje de carrito vacío. En todos los casos los subtotales y el total se actualizaron correctamente y de forma reactiva.

Separar el estado en un servicio, los cálculos en pipes y la interfaz en componentes hace que el código sea más ordenado y fácil de mantener. Si se necesita cambiar cómo funciona el carrito solo se modifica el servicio, y si se necesita cambiar un cálculo solo se modifica el pipe correspondiente, sin tocar el resto de la aplicación.
